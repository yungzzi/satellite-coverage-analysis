# 浙江 11 地市边界与网格基线

> 基线版本：`datav-areas_v3-amap-2021-05-wgs84-v1`  
> 验收日期：2026-08-31

## 1. 为什么要单独冻结一套边界

“杭州市”“宁波市”只是名称，不足以保证不同系统使用的是同一条行政边界。数据年份、海岛处理、
坐标系和简化精度不同，都会改变 5 km 网格、面积权重、薄弱区域和选星结果。因此本工程不在运行时
临时抓取边界，而是把原始数据、转换方法和计算文件一起冻结并记录哈希。

当前项目基线来自 [DataV.GeoAtlas](https://datav.aliyun.com/portal/school/atlas/area_selector)。页面标明
边界数据来自高德开放平台、版本为 2021.5；[阿里云 DataV 地图数据说明](https://help.aliyun.com/zh/datav/datav-7-0/user-guide/map-data-format-1)
说明其地图数据使用 GCJ-02。卫星轨道地面点采用 WGS84 语义，所以 DataV 原始坐标不能未经转换直接参与几何计算。

## 2. 文件分层

```text
data/geo/
├─ raw_datav_gcj02/
│  ├─ 330000.json              # 原始浙江省 GCJ-02 字节快照
│  └─ 330100.json ... 331100.json # 原始 11 地市快照
├─ 330000.json                 # 归一化后的 WGS84 计算边界
├─ 330100.json ... 331100.json
└─ metadata/zhejiang_boundaries.json # 数据版本、转换方法和三类 SHA-256
```

- `raw_datav_gcj02/` 是审计依据，不直接进入卫星覆盖计算。
- `data/geo/<adcode>.json` 是运行时读取的 WGS84 文件。
- 清单分别记录原始文件哈希、转换文件哈希和纯几何哈希。文件被改动后，自检会立即失败。

## 3. 坐标转换口径

脚本 `src/prepare_zhejiang_boundaries.py` 使用固定版本
`gcj02_to_wgs84_iterative_v1`。白话地说，它不是“经纬度统一减一个经验值”，而是：

1. 先猜一个 WGS84 坐标；
2. 用标准 GCJ-02 正向公式把该猜测投回 GCJ-02；
3. 比较投回点与原始点的误差；
4. 用误差修正猜测，最多迭代 12 次；
5. 再做 WGS84→GCJ-02 回代验收。

12 份边界所有坐标的最大回代误差为 `2.984e-13°`，低于自检阈值 `1e-9°`。这里验证的是
“转换数值是否自洽”；它不意味着高德数据本身具有同等级的测绘绝对精度。

转换后的 GeoJSON 明确写入：

```json
{
  "source_dataset_crs": "GCJ-02",
  "geometry_crs": "EPSG:4326",
  "coordinate_transform": "gcj02_to_wgs84_iterative_v1"
}
```

`load_city_boundary(...)` 会检查 `geometry_crs`。若调用者把 WGS84 文件误称为其他坐标系，程序会
直接拒绝，而不是带着几百米级偏移继续计算。

## 4. 拓扑修复

原始浙江省 `330000` 和舟山市 `330900` 几何含自相交，不能直接用于可靠裁剪。脚本只对无效几何
执行 `shapely_make_valid_polygonal_v1`，提取有效面并做并集；其余 10 份不修改拓扑。是否修复已写入
每个计算文件的 `topology_repair` 字段，避免隐式改变边界。

## 5. 11 市 5 km 网格验收结果

固定口径：浙江 Lambert 方位等面积投影、5,000 m 格长、固定原点 `(0,0)`；方格与城市边界裁剪后，
每个连通裁剪单元取内部代表点做覆盖判定，裁剪面积作为权重。下表“单元数”包含海岛等离散面形成的
独立裁剪单元；“面积”是这套边界在冻结等面积投影下的计算面积，不应与其他年份或其他口径的统计面积混用。

全部城市均满足：

- 网格非空，所有裁剪单元面积为正；
- 每个代表点都由自己的裁剪几何覆盖；
- 裁剪单元面积总和与投影后城市边界面积误差小于 `0.01 m²`；
- Targeted 所用面积加权形心与同一批网格、同一组面积权重一致。

11 市边界并集与浙江省边界的对称差为 `0.2836%`，城市间重叠为 `0.0027%`。这说明同一来源的省级层
和地市层基本一致，但并非数学上完全相同；程序保留这个差异，不会为了“凑成零”而擅自改行政边界。

## 6. 生成与验收命令

首次获取或明确更新来源时：

```powershell
python src\prepare_zhejiang_boundaries.py --refresh
```

日常离线重建使用已冻结原始快照，不访问网络：

```powershell
python src\prepare_zhejiang_boundaries.py
```

综合验收：

```powershell
python src\validate_zhejiang_boundaries.py
python src\validate_region_grid.py
python src\validate_siriagent_skill.py
```

## 7. 与 SIRIAgent 平台边界的关系

这套数据已经足够继续项目开发和本地 Skill 验收，不再阻塞 11 市计算。但它尚不能证明与 SIRIAgent
平台内部边界逐点相同。正式联调时只需问研发一件事：平台是否要求新 Skill 必须复用其现有边界。

- 若不要求：继续使用本项目冻结基线，并把版本/哈希随结果返回。
- 若要求：索要平台边界原文件、版本和坐标系，生成新的版本化基线并重新跑上述验收。
- 禁止把平台未知坐标系文件直接覆盖进 `data/geo/`，也禁止静默混用两套边界。
