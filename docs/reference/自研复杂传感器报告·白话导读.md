## 0. 一句话：这份报告在解决什么

**旧版程序**假设卫星的相机永远正对着地球正下方（天底）拍。

**现实是**：真实遥感卫星的相机**会侧着看、会转着扫、会盯着某个目标看**——老师要的正是这种"更真实的拍法"。

这份报告就回答了三个问题：

1. 卫星**机身在太空里朝哪**（姿态）；
2. 相机**镜头朝哪、能偏多少**（指向）；
3. 镜头**能照到多大、什么形状**（视场）。

把这三样都算对，就能回答"某一刻，这颗星到底能不能拍到目标点"。

---

## 1. 用一个最贴切的比方：卫星 = 一台在天上飞的相机

想象你手里举着一台相机，三个"可调"的东西决定了你能拍到什么：

| 东西 | 比方 | 报告里的名词 | 常见选项 |
| --- | --- | --- | --- |
| 相机怎么握 | 是面朝地、朝太阳、还是沿飞行方向 | **姿态** | 对地 / 对速度 / 对太阳 + 一组偏移角度 |
| 镜头朝哪 | 镜头本身还能再偏 | **指向** | 固定偏个角度 / 一直追着目标 / 转圈扫 |
| 镜头视角 | 能照到多大范围、什么形状 | **视场** | 圆 / 方 / 圆环 / 一条带 / 聚光灯 |

**关键一句（背下来口头禅）**：

> 镜头是焊在相机机身上的——**机身怎么摆，镜头就朝哪**。所以要先定机身朝向（姿态），镜头方向（指向）只是在机身朝向的基础上再偏一点点。

---

## 2. 四件事分开讲清楚

### 2.1 姿态：机身朝向（报告第 2 章）

卫星不是只朝正下方看。它可能：

- **对地看**：机身的"脸"正对地球（默认，大多数遥感星）；
- **对速度/飞行方向**：机身的"头"朝飞行方向（SAR/通信常用）；
- **对太阳**：机身的某个轴朝太阳（能源/散热考虑）。

每种朝向，程序都用卫星的**位置**和**速度**（这两样轨道计算已经给出）算出一个"机身坐标系"——也就是机身三个轴在太空里分别指向哪。这个坐标系就是一个 3×3 的"方向表"，后面镜头方向都要靠它换算。

**你只需要懂**：姿态决定了"相机机身在太空里的朝向"，它由卫星的位置和速度算出来，还可在上面叠加一个固定的"额外转动"（就是侧摆/偏置，工程师手动给的角度）。

### 2.2 指向：镜头朝哪（报告第 3 章）

有了机身朝向，镜头还能这样偏：

- **固定指向**：镜头相对机身偏一个固定角度（就是"侧摆"，往左边或右边斜着拍）；
- **目标指向**：镜头**一直盯着地面某个目标点**（凝视观测，适合高分辨率定点拍）；
- **入射高度指向**：镜头贴着一个"离地指定高度的假想球面"看过去（边缘大气观测那类）；
- **旋转扫描**：镜头像**泛光灯一样转圈扫**，一帧一帧扫过一大片（适合大范围快速普查）；
- **外部指向文件**：用一个大表逐时刻告诉镜头朝哪（高级用法，先不管）。

每种指向，程序都在每个时刻算出一个"镜头正对的方向"，也就是**视轴**。

**你只需要懂**：指向决定了"镜头正对哪个方向"，本质是"在机身朝向上再加一个角度偏置/转动/跟踪"。

### 2.3 视场：镜头能照到什么形状（报告第 4 章）

镜头不是只有"圆的"。有这几种常见形状：

| 类型 | 像什么 | 说明 |
| --- | --- | --- |
| 简单圆锥 | 手电筒 | 普通相机，照一个圆 |
| 矩形 | 广角方照片 | 照一个矩形（长宽各给一个半角） |
| 复杂圆锥 | 甜甜圈 | 中间有个洞（照一个环） |
| 半功率 | 聚光灯 | 用频率和天线直径算"光斑多大"（雷达/通信） |
| SAR | 一条带子 | 合成孔径雷达，斜着扫出一条条带（自己的一套"入射角带"） |

**你只需要懂**：每种视场就是一组"夹角限制"——目标方向和镜头正对方向的**夹角**要落在某个范围内才算"照得到"。圆就是"夹角≤半角"；方就是"横竖两个方向夹角各≤半角"；环就是"夹角在内外两个角度之间"；条带就是"夹角在一个区间、且不是正前方/正后方"。

### 2.4 约束：额外"什么时候才算数"（报告第 5 章）

除了"照得到"，还会加些**质量/合规判断**：

- 距离不能太远、仰角不能太低（大气路径长、画质差）；
- 目标与卫星的相对速度、角度变化率要在范围内（链路稳定）；
- 太阳/月球不能直射镜头（光学传感器怕被亮瞎）；
- 太阳仰角、昼夜条件（照地面要白天还是黑夜）。

**你只需要懂**：约束就是"附加的准入条件"，满足才把这个时间点算作有效覆盖。

## 3. 这些到底怎么算出来（原理一层）

全景一句话：

> **每个时刻**：算出卫星在哪 → 算出机身朝哪（姿态）→ 算出镜头朝哪（指向）→ 算出目标点相对镜头在哪 → 看两者夹角是否落进视场范围 → 是就"这一刻覆盖"。

每个时刻重复一遍，把所有"覆盖的时刻"连起来，就是**覆盖窗口**（开始/结束/时长）——这和旧版程序输出的东西一模一样，只是判据变得更真实。

所有公式干的都是同一件事：**算"目标方向"和"镜头正对方向"之间的夹角**。旧版假设镜头永远朝正下方，所以只需要算"目标和正下方的夹角"；现在镜头会偏、会转、会盯，就多了"先算出镜头到底朝哪"这一步。

**为什么一定要知道"镜头朝哪"**：因为机身朝向变了，镜头正对方向就变了（口头禅 1）。举个直觉例子：卫星机身侧转 30°，镜头正对方向就往旁边偏了 30°，同一时刻能照到的地方就从正下方挪到了旁边——所以**姿态和指向会改变覆盖结果**。

## 4. 怎么证明算对了（报告第 8 章）

这是你最需要、也是最容易听懂的部分：

**用 ATK（专业航天仿真软件，国科大做的）做对照。** 同一个输入（同样的卫星轨道、同样的杭州目标点、同一时段），分别让 ATK 和我们的程序算，比覆盖窗口：

| 传感器类型 | 窗口数差 | 总时长偏差 |
| --- | --- | --- |
| 复杂圆锥（甜甜圈） | 0 | -3.0% |
| 矩形 | 0 | -1.6% |
| 半功率（聚光灯） | 0 | -3.2% |
| SAR（条带） | 1 | -29%（唯一待校准的一项，报告里有说明） |

意思是：**四种复杂传感器里，三种和 ATK 几乎一模一样（3% 以内），SAR 也接近（还在校准）。**

另外：

- **旧版没改坏**：普通圆锥（旧版默认）的算法结果完全不变（零回归），以前能用的现在照样能用；
- **而且比 ATK 更"确定"**：ATK 的旋转扫描有个毛病——每次启动镜头初始相位不一样，同参数两次结果不同；我们把初始角度写死了，**同参数每次结果一样**。

这条是"凭什么信"的底气：**跟业界软件对过、且旧功能没动、还修了 ATK 的一个不确定性。**

## 5. 你自己怎么讲（照着背/照着说）

### 30 秒版

> 以前我们的程序假设卫星永远正对地面拍。其实真实卫星会侧着看、转着扫、盯着看，我把这些都做进去了：先算卫星机身朝哪，再算镜头朝哪、能照多大范围，然后判断目标有没有进到镜头里。用 ATK 专业软件对照过，四种传感器误差都在 3% 以内，旧版结果也完全没变。

### 2 分钟版（分三段）

**为什么做**：旧版只能正下方看，保守；真实遥感星会侧摆/凝视/扫描，感知范围更大，所以要把"姿态+指向+视场"建模出来。

**怎么算**：每个时刻，卫星轨道位置 → 机身朝向（姿态，由位置速度算出）→ 镜头方向（指向，在机身上叠加）→ 目标方向 → 看两者夹角是否在镜头视场内 → 是就覆盖。公式本质上就是"算夹角"，只是从"固定朝下"变成了"任意朝向"。

**凭什么信**：①跟 ATK 对照，圆/方/环/聚光四种都在 3% 以内；②旧版普通圆锥结果零改动，没破坏原功能；③旋转扫描我们是确定性的，ATK 反而不确定。

### 三个口头禅（关键时刻用）

1. 镜头焊在机身上——机身怎么摆，镜头就朝哪；
2. 覆盖 = 目标方向和镜头正对方向的夹角，小于镜头的半角；
3. 跟 ATK 对过，四种都在 3% 以内，旧版没变。

## 6. 哪些必须懂、哪些可以跳过

**必须懂（会讲就行）**：

- 姿态/指向/视场分别是什么（2.1/2.2/2.3）；
- 为什么姿态会改变覆盖（镜头跟着机身转）；
- 凭什么信（跟 ATK 对照 + 零回归 + 更确定）；
- 三个口头禅。

**第一次完全可以跳过**：

- 所有公式（1.1 到 4.8，那些 `R₃(GMST)`、四元数、`atan2` 都给代码和验证用的）；
- 4.4 的复杂圆锥钟角、5.2 的约束明细表（除非真要配具体传感器）；
- 8.3 那份逐项对标表（知道"≈3% 内"就够）。

## 7. 常见疑问（可能被问到的）

**"姿态改了对覆盖有啥影响？"**
镜头跟着机身走。机身侧转 30°，镜头就偏 30°，照到的地方从正下方挪到旁边。

**"为什么矩形视野比圆的照得更广？"**
同样半角 45°，圆的面积约 6360 平方度，矩形是 8100 平方度——所以矩形照到的时间更长。

**"旋转扫描为什么更确定？"**
ATK 的转圈起始角度每次随机，我们把它固定成"分析开始的时刻对应的角度"，所以同一参数每次结果一样，可复现。

**"SAR 为什么差 29%？"**
SAR 有个"雷达爸爸高度"的参数，ATK 这个版本处理得有点特殊；我们已经接近，还差最后一步校准（报告 P3 待办）。
