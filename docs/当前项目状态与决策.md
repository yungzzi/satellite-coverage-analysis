# 当前项目状态与决策

## 现在要交付什么

将“卫星覆盖分析 + 选星”做成研究院 SIRIAgent 可调用的 Skill。当前按 Agent 与引擎同机
直接执行 Python；不需 FastAPI、MCP、Docker 或数据库。只有平台运行架构证实不同机时才增加网络服务壳。

## 已确定的边界

- 覆盖结果的事实来源始终是卫星覆盖窗口，不用单个“可/不可覆盖”布尔值替代。
- 区域采用裁剪 5 km 米制格网：每格的裁剪面积为权重，内部代表点只用于覆盖判定，不带半径圆。
- 目标优先全部面积达标；不可行时才明确报告并降级为至少 90% 面积达标。
- 分辨率只筛候选卫星；光学幅宽按矩形、SAR 按原生入射角带计算。
- 复杂传感器、姿态与指向是固定场景 Profile，不做姿态行为优化或成像调度。
- ATK 只保留为 Windows 本机短期对拍参考，不参与服务、Docker 或 Linux 部署。

## 已完成

1. 自研覆盖引擎已具备 SimpleCone、Rectangular、Conical、HalfPower、SAR，以及姿态、指向和约束。
2. 新增 `src/region_grid.py`：固定投影/原点的裁剪格网、面积权重、代表点和调试 GeoJSON。
3. `src/validate_region_grid.py` 已验证杭州边界在 5 km / 2.5 km 下的面积守恒与代表点内部性。
4. 已完成逐星逐网格窗口、区域指标和五项区域选星，支持 K=1～3。
5. 已完成 `src/siriagent_skill/` 和项目级 Codex Skill：参数说明、缺参追问、JSON 调用和人类可读输出；
   普通请求按预设运行，高级请求可传全局 `sensor_profile` 和逐星 `satellite_profile_overrides`，并在结果回显
   实际生效配置。
6. 已冻结浙江省及 11 地市边界：保留 DataV/高德 2021-05 的 GCJ-02 原始快照，使用固定方法转换为
   WGS84 计算文件，并通过哈希、坐标回代、全市 5 km 网格和省市并集自检。

## 接下来的实现顺序

1. 映射平台 110 星目录/TLE，并补齐真实逐星光学/SAR Profile。
2. 用 11 市真实 5 km 网格做全池性能基准，确定同步调用上限和是否需要缓存/任务队列。
3. 向平台研发取得注册样例、`script_id` 映射、Python 环境、超时与输出体积规范。
4. 在 SIRIAgent 测试环境完成“意图→追问→执行→结果页”联调；仅异机时增加 FastAPI。

## 尚需外部确认

- 平台 skill 的注册样例、`script_id` 位置、runner 是否同机及调用时限；
- 平台是否要求改用其自带城市边界；如要求，需取得其边界版本、坐标系和文件，与当前冻结基线比较，
  不能只按“同名城市”假定几何完全相同；
- 平台要表达“点、面、推扫面阵、SAR 入射角”的最终输入字段。
