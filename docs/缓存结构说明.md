# 缓存目录结构说明（data/tle_cache/）

> 本目录由程序自动维护（已 gitignore，不入库）；这份说明文档入库，方便随时查阅。
> 整个目录可以随时删除，程序会自动重新下载。

## 目录结构

```
data/tle_cache/
├── README.txt          本说明（程序每次启动自动生成一份）
├── active.tle          全集现役 TLE
├── meta/               搜索结果"卫星档案表"（CSV）
├── name/               按名字搜索的 TLE
├── norad/              单颗星 TLE
└── resolved/           成品：每个收藏夹合并的 TLE（人看这个文件夹即可）
```

## 各文件来源与用途

| 文件 | 内容 | 来源 | 生成时机 |
| --- | --- | --- | --- |
| active.tle | 下载时刻"所有现役卫星"的 TLE 全集（约 1.6 万条） | CelesTrak `gp.php?GROUP=active` | 解析需要时自动下载；网络差会失败并自动退回单星下载 |
| meta/关键字_meta.csv | 卫星档案表：名字/编号/所属国/发射日期/轨道参数 | CelesTrak `records.php?NAME=关键字&PAYLOADS=1&ONORBIT=1` | 搜索时按关键字缓存 |
| name/关键字.tle | 名字匹配的 TLE（含该名字的所有匹配对象） | CelesTrak `gp.php?NAME=关键字` | 名字规则解析、全集不可用时 |
| norad/编号.tle | 单颗星的 TLE | CelesTrak `gp.php?CATNR=编号` | 编号清单里某颗星在全集查不到时 |
| resolved/夹名.tle | 一个收藏夹全部星的合并 TLE（标准 3LE 文本） | 程序从上面的缓存拼出 | 点"解析下载"时 |

## 常见疑问

- **active.tle 里有什么？是所有下载过的星吗？**
  不是。它是"下载那一刻的整个现役目录快照"，包含当时所有现役卫星；
  不是"查过什么就存什么"。成功下载后，绝大多数单星/名字查询都直接在本地查它。
- **meta 为什么是 csv，其他是 tle？**
  meta 是"表格数据"（档案），CSV 是表格标准格式；其他是"轨道数据"，
  标准格式是 TLE（3 行一组）。TLE 文件统一用 `.tle` 后缀。
- **碎片/火箭体会混进来吗？**
  不会。搜索接口带 `PAYLOADS=1&ONORBIT=1` 参数，只返回在轨载荷；
  名字规则解析时再用这批载荷编号做白名单过滤（YAOGAN 为 165 颗）。
- **我只需要看 resolved/ 吗？**
  是的。resolved/ 是给人看的成品；其余是程序中间缓存。注意 resolved 是
  "点解析下载那一刻"的快照，改完收藏夹后要重新解析才会更新。
- **缓存多久更新？**
  默认 24 小时过期自动更新；GUI ③页"缓存管理"可查看每个文件的更新时间并一键清空。
