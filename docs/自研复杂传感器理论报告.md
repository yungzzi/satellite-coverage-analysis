## 摘要

自研引擎当前的覆盖模型是"**天底固定圆锥 + 最小仰角**"（视场半角 $\eta$ = 视线张角，默认 10°）。要覆盖 ATK 的全部能力，需要回答三个问题：

1. **姿态**：卫星本体在空间怎么指向（对地、对速度、对太阳、固定、旋转、凝视）？
2. **传感器指向**：视轴相对星体怎么偏（侧摆固定角、切球入射、追目标、旋转扫描、外部文件）？
3. **视场形状**：视轴周围多大的立体角算"看得见"（圆锥、矩形、内外锥+钟角、半功率波束、SAR 条带）？

本报告给出完整数学方案，核心思想只有一句话：

> **覆盖判定 = 把目标方向矢量变换到传感器坐标系，再做一组"视场不等式"检查。**

所有量（位置、速度、姿态、视轴、目标方向、太阳/月球方向）都是时刻的解析函数，因此整个计算链路是**确定性**的——这比 ATK 的 Spinning 跨实例相位不锚定（版本缺陷，§10.18）更可靠。ATK 已有实测数据（SimpleCone45 对拍：ATK 69 窗口 vs 自研 70、匹配 69；Conical 退化一致；Rectangular 74 窗口；SAR 6 窗口；HalfPower 5 窗口；姿态族 0 vs 4 端到端差异；Targeted GUI 91.282 s 窗口）全部可作为对拍基准（8.3 节）。

# 第 1 章　坐标系与姿态表示基础

> **本章导读（白话）**：要回答"卫星能不能拍到目标"，得先把"卫星在天上哪里、机身在太空里朝哪"翻译成程序能算的三维数字。本章就是干这个的——定坐标系、学怎么表示"朝向"。
>
> **背后的理论**：航天里描述"朝向"（姿态）有两种常用的数学工具：**旋转矩阵**（直观、直接）和**四元数**（无奇点、方便做平滑插值）。坐标系要分"惯性系（固定在天球、不随地球转）"和"地固系（跟着地球转）"，因为卫星相对惯性系运动，而目标和观测点跟着地球转——两者之间靠地球自转角（GMST）旋转换算。这些是卫星轨道/姿态计算的公共地基，各任务软件通用。

## 1.1 需要的坐标系

| 坐标系 | 说明 | 用途 |
| --- | --- | --- |
| ECI（TEME） | SGP4 直接输出的惯性系（近真赤道/平春分点系） | 轨道外推、惯性姿态（P1/P2/P4） |
| ECEF（ITRS） | 随地球自转的地固系 | 星下点、目标坐标、ECF 姿态（P0/P3）、方位/仰角 |
| 轨道局部系（VVLH/LVLH） | 随卫星轨道运动的本地系 | 姿态基准、传感器本地角定义 |
| 体坐标系（Body） | 卫星本体 | 传感器安装、姿态偏移 |
| 传感器坐标系（Sensor） | 以传感器为原点、视轴为 +z | 视场不等式判定 |
| ENU（站心/表面局部系） | 目标点或卫星处的北-东-天 | 地面仰角/方位角、太阳仰角 |

坐标系间关系：

```
ECI(TEME) ──GMST/章动/极移──▶ ECEF(ITRS) ──本地子午线──▶ ENU(目标点/卫星)
    │                                │
    └───────── VVLH 轨道系 ──────────┘
                    │
                 体坐标系（姿态族/偏移四元数）
                    │
                 传感器坐标系（指向 → 视轴）
```

**TEME → ECEF**：工程上取

$$
\mathbf{r}_{\mathrm{ECEF}} = R_3(\mathrm{GMST})\, \mathbf{r}_{\mathrm{TEME}} \tag{1.1}
$$

**为什么只需要转一个角**：卫星位置由 SGP4 给出时是在惯性系（视地球不动），而目标坐标是"钉在地球上"的。两者差的就是地球自转——绕地球自转轴转过 GMST 角度即可对齐。真实链路还有章动、极移，但对覆盖判定只差弧秒级（地面约百米、窗口亚秒级），远小于 TLE 本身误差（公里级），所以工程上取 GMST 一个旋转就够了。这就是"深入浅出"里的取舍：够用就行，不为微小精度引入复杂度。

其中 $R_3$ 为绕 Z 轴旋转，GMST 为格林尼治平恒星时。真实链路还包括章动（真赤道）与极移，但对覆盖判定的影响在弧秒级（地面 ~100 m、窗口亚秒级），远小于 TLE 时效误差（公里级），本报告采用 GMST-only 约定，与 skyfield `subpoint()` 的口径差异已在现有报告中量化（仰角 1° 级、边界分钟翻转仅在恰好压线 10.0° 时出现）。

**ECEF 速度**：由 ECI 速度扣除地球自转牵连速度：

$$
\mathbf{v}_{\mathrm{ECEF}} = \mathbf{v}_{\mathrm{ECI}} - \boldsymbol{\omega}_\oplus \times \mathbf{r}_{\mathrm{ECEF}} \tag{1.2}
$$

这是 P0/P3 姿态族（"固连系速度"）所需。

## 1.2 旋转矩阵与四元数

旋转矩阵 $C$ 满足 $C^{\mathsf{T}}C = I$、$\det C = +1$。**约定**：$C$ 的列是"新系基向量在旧系中的坐标"，即对列向量 $\mathbf{v}$：$\mathbf{v}_{\mathrm{new}} = C \cdot \mathbf{v}_{\mathrm{old}}$。

**四元数** q = (qs, qx, qy, qz)，|q| = 1，旋转向量 v：

$$
\mathbf{v}' = \mathbf{v} + 2q_s\,(\mathbf{q}_v \times \mathbf{v}) + 2\,\mathbf{q}_v \times (\mathbf{q}_v \times \mathbf{v}) \tag{1.3}
$$

其中 q_v = (qx, qy, qz)。四元数复合（先 q₁ 后 q₂）：

$$
q = q_2 \otimes q_1 \tag{1.4}
$$

复合公式（标准 Hamilton 积）：

$$
(q_s, \mathbf{q}_v) \otimes (p_s, \mathbf{p}_v) = (q_s p_s - \mathbf{q}_v \cdot \mathbf{p}_v, \ \ q_s \mathbf{p}_v + p_s \mathbf{q}_v + \mathbf{q}_v \times \mathbf{p}_v)
$$

**欧拉角/YPR → DCM**：ATK 的转序（Euler：121/123/…/323；YPR：YPR/YRP/…/RPY）按**本体连续旋转（intrinsic）**约定：

$$
R(\text{seq}="123";\, r_1, r_2, r_3) = R_3(r_3)\, R_2(r_2)\, R_1(r_1) \tag{1.5}
$$

$$
R(\text{YPR}) = R_{\mathrm{roll}}\, R_{\mathrm{pitch}}\, R_{\mathrm{yaw}} \tag{1.6}
$$

其中 R₁/R₂/R₃ 为绕 x/y/z 的基本旋转矩阵。**注意**：欧拉/YPR 的正负号与内外旋约定需与 ATK 输出对拍校准（8.3 节），报告中所有公式采用上述显式约定，一旦实测偏差即翻转对应项。

## 1.3 从 SGP4 到 r、v，以及太阳/月球方向

现有引擎已通过 skyfield 的 `EarthSatellite.at(t)` 获得卫星 TEME 位置与速度（`geocentric.position.km` / `.velocity.km_per_s`），并由 `subpoint()` 得到星下点经纬高。扩展后还需要：

- TEME 位置速度 $\mathbf{r}_{\mathrm{TEME}}, \mathbf{v}_{\mathrm{TEME}}$（已可得）；
- ECEF 位置 $\mathbf{r}_{\mathrm{ECEF}}$ 与速度 $\mathbf{v}_{\mathrm{ECEF}}$（由 (1.1)(1.2)）；
- 太阳/月球地心方向 $\hat{\mathbf{s}}(t)$、$\hat{\mathbf{m}}(t)$（P4 姿态与光照约束用）。

**太阳/月球方向**：生产实现用 skyfield 的 `load('de421.bsp')`（项目已有依赖，离线缓存后可复用）；无星历时可用 Meeus《Astronomical Algorithms》第 25 章低精度解析公式（太阳标称 ~0.01°、本机用 DE430 测试子集对拍 0.21°；月球 ~0.3°）。光照约束（昼夜判断、规避角）对 0.5° 级误差不敏感。

**为什么要算太阳/月球**：P4 "太阳对齐"姿态需要太阳方向；光照约束（昼夜、别让太阳直射镜头）需要太阳和月球相对卫星/目标的方向。它们是"地心方向"，再转到一个本地坐标系看仰角、夹角即可。用解析公式能省去下载星历，精度对 0.5° 级的光照判断足够。

# 第 2 章　卫星姿态：必要性分析与构造公式

> **本章导读（白话）**：机身朝哪（姿态）直接决定镜头朝哪。本章讲几类标准"摆法"——对地、对速度、对太阳——以及怎么用公式"算"出来。
>
> **背后的理论**：航天界用**轨道局部坐标系**（如 VVLH：正下方 + 飞行方向 + 第三轴补右手系）作为描述卫星朝向的基准，这是业界约定俗成的标准。不同任务需要不同基准朝向：对地（成像/测绘）、对速度（SAR/通信）、对太阳（能源/热控）。在此基础上再加一个"偏移四元数"，就是在基准上再转一个固定角度——这就是"侧摆/偏置"的数学形式。

## 2.1 姿态为什么决定覆盖

传感器视轴在惯性空间的方向由**两级旋转**决定：

$$
\mathbf{b}_{\mathrm{ECI}} = C_{\mathrm{body}\leftarrow\mathrm{ECI}} \, \mathbf{b}_{\mathrm{sensor}} \tag{2.1}
$$

其中 $C_{\mathrm{body}\leftarrow\mathrm{ECI}}$ 由整星姿态决定，$\mathbf{b}_{\mathrm{sensor}}$ 由传感器指向（第 3 章）决定。覆盖判定最终检查目标方向是否落在视轴周围的视场立体角内。因此**姿态不参与"目标是否在地球上"这类粗判，但决定视轴指向哪里、足印落在哪里**——侧摆、凝视、扫描、SAR 侧视都依赖姿态/指向的精确建模。

## 2.2 必要的姿态全集（与 ATK EVeProfile 0-4 对齐）

ATK 的整星标准姿态族（`ICEnum.h` 枚举 `EVeProfile`，用户 GUI 保存场景为 ground truth，§10.33）：

| 编号 | ATK 名称 | 物理语义 | 典型用途 |
| --- | --- | --- | --- |
| 0 | 固连系VVLH（对天底定向 + 固连系速度约束） | Z 轴对地心，X 轴尽量沿 ECF 速度 | 默认对地遥感（大多数低轨成像/测绘） |
| 1 | 惯性系VVLH（对天底定向 + 惯性系速度约束） | Z 轴对地心，X 轴尽量沿 ECI 速度 | 对地遥感另一常见约定（差异仅在 X 轴绕天底的滚转） |
| 2 | ECI 对速度定向（+ 天底约束） | X 轴对 ECI 速度，Z 轴尽量对地 | SAR 沿迹向、姿态机动、对地 + 速度复合 |
| 3 | ECF 对速度定向（+ 天底约束） | X 轴对 ECF 速度，Z 轴尽量对地 | 地面轨迹扫描、沿地速方向凝视 |
| 4 | 太阳对齐（+ 天底约束） | X 轴对太阳，Z 轴尽量对地 | 能源/热控优先任务、太阳同步轨道对日定向 |

ATK GUI 中还有**固定姿态**（相对参考轴固定，四元数）、**旋转姿态**（绕固定轴旋转，参考历元+角速度+初始偏移角）、**目标指向姿态**（整星指向目标，默认 Z 轴对齐）。实验已定案（§10.34）：rc.5 的 Legacy 姿态体系对这三类**不序列化、不生效**（无 ground truth），需求已由传感器级指向（Fixed/Spinning/Targeted，第 3 章）承担。因此自研引擎的**整星姿态实现标准族 0-4 + 偏移（四元数/欧拉角/YPR 角三选一，GUI 下拉）**即可覆盖 ATK 实际生效的全部能力；固定/旋转/凝视姿态需求在传感器指向层实现，物理效果相同且更通用。

**"哪些是必要的"结论**：对覆盖分析而言，最小必要集 = **P0（默认对地）+ 偏移四元数（侧摆）**；完整集 = P0-P4 + 偏移四元数。P2/P3（速度对齐）与 P4（太阳对齐）在"对地遥感"主场景中非默认，但老师要求的"姿态改变后感知范围变大"对应的正是**偏置（侧摆）与凝视/扫描**，这些由传感器指向层承担，P0 基准 + 指向偏置即可表达。

**为什么这些"摆法"就够了**：姿态本质是"机身三个轴各自朝哪"，而覆盖几何只关心"镜头正对方向"。镜头通常装在机身某个面上，所以只要知道机身朝向 + 镜头相对机身的偏置，就完全定了镜头方向。上面五类 + 偏移已覆盖"机身可能的各种朝向"；再花哨的姿态（如随时机动变向）属于控制/调度层面，不改变"给定朝向下覆盖几何是什么"这一层。

## 2.3 标准姿态族的解析构造

统一记法：$\hat{\mathbf{r}} = \mathbf{r}/|\mathbf{r}|$（天底方向为 $-\hat{\mathbf{r}}$），$\mathbf{v}$ 为对应速度（P0/P3 用 $\mathbf{v}_{\mathrm{ECEF}}$，P1/P2 用 $\mathbf{v}_{\mathrm{ECI}}$），$\hat{\mathbf{s}}$ 为太阳方向（ECI）。

**P0 / P1（天底定向 + 速度约束）**：

$$
\hat{\mathbf{z}} = -\hat{\mathbf{r}}, \qquad
\hat{\mathbf{x}} = \frac{\mathbf{v} - (\mathbf{v}\cdot\hat{\mathbf{z}})\,\hat{\mathbf{z}}}{\lvert \mathbf{v} - (\mathbf{v}\cdot\hat{\mathbf{z}})\,\hat{\mathbf{z}} \rvert}, \qquad
\hat{\mathbf{y}} = \hat{\mathbf{z}} \times \hat{\mathbf{x}} \tag{2.2}
$$

即：Z 轴严格指向地心；X 轴取速度在水平面（$\perp \hat{\mathbf{z}}$）上的投影并归一化（圆轨道下就是速度方向；椭圆轨道下速度含径向分量，故"不一定重合"）。Y 轴补成右手系。**注**：$\hat{\mathbf{x}}$ 的退化情形（$\mathbf{v}$ 与 $\hat{\mathbf{z}}$ 平行，即速度沿径向）实际不会发生（轨道速度始终近似垂直于径向），代码仍加分母防护。

**P2 / P3（速度定向 + 天底约束）**：

$$
\hat{\mathbf{x}} = \hat{\mathbf{v}}, \qquad
\hat{\mathbf{z}} = \frac{-\hat{\mathbf{r}} + (\hat{\mathbf{r}}\cdot\hat{\mathbf{x}})\,\hat{\mathbf{x}}}{\lvert -\hat{\mathbf{r}} + (\hat{\mathbf{r}}\cdot\hat{\mathbf{x}})\,\hat{\mathbf{x}} \rvert}, \qquad
\hat{\mathbf{y}} = \hat{\mathbf{z}} \times \hat{\mathbf{x}} \tag{2.3}
$$

即：X 轴严格沿速度；Z 轴取天底方向在 $\perp \hat{\mathbf{x}}$ 平面上的投影（"尽量对地"），Y 补右手系。

**P4（太阳对齐 + 天底约束）**：

$$
\hat{\mathbf{x}} = \hat{\mathbf{s}}, \qquad
\hat{\mathbf{z}} = \frac{-\hat{\mathbf{r}} + (\hat{\mathbf{r}}\cdot\hat{\mathbf{x}})\,\hat{\mathbf{x}}}{\lvert -\hat{\mathbf{r}} + (\hat{\mathbf{r}}\cdot\hat{\mathbf{x}})\,\hat{\mathbf{x}} \rvert}, \qquad
\hat{\mathbf{y}} = \hat{\mathbf{z}} \times \hat{\mathbf{x}} \tag{2.4}
$$

**体坐标系 DCM**：三轴为列向量（在参考系 ECI 或 ECEF 中表达）：

$$
C_{\mathrm{body}\leftarrow\mathrm{ref}} = [\,\hat{\mathbf{x}}\ \ \hat{\mathbf{y}}\ \ \hat{\mathbf{z}}\,] \tag{2.5}
$$

若基准在 ECEF（P0/P3）而最终需要 ECI 表达，左乘 (1.1) 的逆变换即可。

## 2.4 偏移四元数（侧摆/固定偏置）

ATK GUI 的"偏移角/偏移四元数"是在基准姿态上叠加的固定旋转。XML 记录 $q_x$、$q_y$、$q_z$，标量 $q_s$ 由单位化隐含（§10.33 注明无非零 ground truth，先按 $q_s = +\sqrt{1-\lvert \mathbf{q}_v \rvert^2}$ 对待）。最终体姿态：

$$
C_{\mathrm{final}} = C(q_{\mathrm{off}})\, C_{\mathrm{base}} \tag{2.6}
$$

即先取标准族基准姿态，再在体坐标上施加偏移旋转。侧摆（roll/pitch 偏置）即令 q_off 为对应角度旋转。

## 2.5 时间离散与数值注意

- 姿态逐时刻计算（与轨道传播同一时间栅格），不假设姿态恒定；
- 每次叉积后重新归一化；投影公式自动处理速度与天底近平行退化；
- 四元数复合后归一化，避免浮点漂移；
- 太阳对齐 P4 在日食/太阳方向与天底近平行时（实际不会，太阳不会穿过地球背后对准卫星正下方）仍由投影公式保护。

**为什么姿态必须逐时刻算、不能当常数**：低轨卫星几分钟绕一圈，机身朝向（尤其"对速度""对太阳"这类）随轨道位置连续变化；侧摆/旋转扫描更是随时间转。若把姿态当成固定值，短窗口会整体错位，长时段会漂移。所以姿态在每个检测时刻都重算一次。

# 第 3 章　传感器指向（Pointing）建模

> **本章导读（白话）**：机身朝向定了，镜头还能再偏。本章讲 6 种"镜头怎么偏"——朝固定一个角度、时刻盯着目标、贴着某高度看过去、转圈扫，以及用外部文件逐时刻指定。
>
> **背后的理论**：每种指向本质都是"给镜头轴一个明确的几何定义"：固定指向 = 常数偏置角；目标指向 = 实时指向目标点方向；入射高度指向 = 视线与某一离地高度的假想球面相切；旋转扫描 = 绕固定轴匀速转动（一个确定性的角度-时间关系）。每一项都是一个可解析求解的几何量，所以能"逐时刻"算出来。

## 3.1 通用框架

传感器坐标系：原点为传感器安装点，视轴为 +z_s，x_s/y_s 为横向参考（x_s 约定沿参考方向，y_s 补右手系，参考方向取沿迹向或本地东向，与 ATK 对拍后固定）。目标方向在传感器系：

$$
\hat{\mathbf{u}}_s = C_{s\leftarrow\mathrm{ECI}}\, \hat{\mathbf{u}}_{\mathrm{ECI}} \tag{3.1}
$$

其中 $\hat{\mathbf{u}}_{\mathrm{ECI}} = (\mathbf{P}_{\mathrm{target}} - \mathbf{r}_{\mathrm{sat}})/\lVert \cdot \rVert$，$C_{s\leftarrow\mathrm{ECI}} = C_{\mathrm{pointing}}\, C_{\mathrm{body}\leftarrow\mathrm{ECI}}$（指向在体坐标内定义）。

## 3.2 默认指向：体 +Z（VVLH 下即天底）

ATK 传感器默认固定于星体、视轴沿体 +Z 轴；在标准姿态族 P0（固连系 VVLH，体 Z 对地）下
它等于天底，但姿态改变（如 P4 太阳对齐）时视轴跟随体轴偏转。因此本文约定：

$$
\mathbf{b} = C_{\mathrm{body}\leftarrow\mathrm{ECI}} \, (0, 0, 1)^{\mathsf{T}} \tag{3.2}
$$

**与现有引擎的关系**：P0 + 无偏移时 (3.2) 严格等于 $\mathbf{b} = -\hat{\mathbf{r}}$（天底），复杂引擎对
“SimpleCone + 天底 + 无姿态/指向/约束”的默认路径直接委托现有 `compute_covered_series`，
保证逐位零回归（含 5 km 目标圆边缘余量与球面口径完全一致）；姿态/指向非默认时走完整
几何（2.1 节：离轴角 $\theta \le \eta \Leftrightarrow$ 足印内 $\lambda \le \lambda_{\max}$，等价性已数值自检）。

## 3.3 Fixed 固定指向

视轴在体坐标（或传感器本地参考系）内固定偏置，五种姿态方法（ATK Connect 语法原文）：

| 方法 | 参数 | 本文约定 |
| --- | --- | --- |
| AzEl | 方位角 Az、高度角 El | 本地 ENU：$\mathbf{b} = (\cos El\cos Az,\ \cos El\sin Az,\ \sin El)$；El 向上为正（向下为负，侧视常用负值） |
| Quaternion | q1 q2 q3 q4（qx,qy,qz,qs） | $\mathbf{b} = q \otimes \text{基准视轴} \otimes q^{-1}$（(1.3)） |
| Euler | 转序 + Rot1/2/3 | (1.5) 的 DCM 旋转基准视轴 |
| YPR | 转序 + Yaw/Pitch/Roll | (1.6) 的 DCM 旋转基准视轴 |
| matrix | d11 d21 d22 d31 d32 d33 | 3×3 旋转矩阵的前 6 个元素（重建规则待 ATK 对拍，见 3.8） |

AzEl 的方位参考方向（沿迹向 or 北向）与 El 符号待与 ATK 对拍校准；默认取"Az 相对沿迹向、El 相对本地水平面、向下为负"。

## 3.4 GrazingAlt 入射高度指向

ATK 语法：`Point <Sensor> GrazingAlt <Azimuth> <GrazingAltitude>`（例：`90.0 10000.0`）。语义：**视轴与"离地高度 H 的同心球面"相切**（切球几何），Azimuth 为相对参考方向的水平偏移。

推导（卫星地心距 r_s，切球半径 a = R + H，单位 km）：

$$
\sin\beta = a / r_s, \qquad \beta = \text{视轴与天底方向的夹角} \tag{3.3}
$$

$$
\delta = 90^\circ - \beta = \text{视轴相对本地水平面的下俯角} \tag{3.4}
$$

$$
\mathbf{b} = (\cos\psi\cos\delta, \ \sin\psi\cos\delta, \ -\sin\delta) \tag{3.5}
$$

其中坐标取本地 ENU（天顶为 +z），$\psi$ 为相对参考方向的方位角。

**自检**：直线 $S + t\,\mathbf{b}$ 到地心 $O$ 的距离恰为 $a$（附录 A，$d = a$ 精确成立）。直观检验：$h = 630$ km、$H = 10$ km 时 $\beta = \arcsin(6388/7008) \approx 65.8^\circ$，$\delta \approx 24.2^\circ$——与 630 km 高度地平线下俯 24.5° 量级一致，即"贴着 10 km 高度的大气层边缘看过去"。入射高度 $H$ 增大 → $\delta$ 减小 → 视线更平。

**为什么用"切球"定义**：入射高度指向是"沿着看远处地面"的姿态，工程上常把它定义成"视线擦过某高度球面"——比直接给仰角更贴近"看边缘/临边观测"的物理。切球条件（视线到地心距离 = 球半径）是这种定义的精确数学表达，而不是近似。

## 3.5 Targeted 目标指向

ATK 语法：`Targeted Tracking <TargetPath> [AboutBoresight] [TrackMode]` 或 `Targeted Fixed <TargetPath> {OrientMethod} <MethodData>`。

- **追踪（Tracking）**：视轴实时指向目标点：

$$
\mathbf{b}(t) = \frac{\mathbf{P}_{\mathrm{target}}(t) - \mathbf{r}_{\mathrm{sat}}(t)}{\lVert \cdot \rVert} \tag{3.6}
$$

　　TrackMode（接收/发射/转发）只影响天线增益方向语义，**对几何覆盖判定等价**（都指向目标），本项目不建模天线增益，三种模式结果相同（已在 GUI 实验验证：Targeted+转发与固定追踪得到同一 91.282 s 窗口）。
- **固定指向（Fixed）**：在"指向目标的方向"上再叠加一个固定偏置姿态（与 3.3 的 Fixed 同款方法）。目标方向为基准视轴，偏置旋转后得到最终视轴。

## 3.6 Spinning 旋转扫描

ATK 语法：`Point <Sensor> Spinning <Azimuth> <Elevation> <ConeAngle> {Continuous|Unidirectional|Bidirectional [Start Stop]} <Rate> <Offset>`。参数：旋转轴方向（Az/El，例 `0 -90` = 指向天底）、锥角 ConeAngle（视轴与旋转轴夹角）、扫描模式、转速（°/s）、初始偏差角 Offset。

**本文确定性模型**（修复 ATK 跨实例相位不锚定缺陷）：

$$
\hat{\mathbf{s}} = \text{旋转轴单位方向（由 Az/El 在传感器本地系给出）}
$$

$$
\mathbf{b}_0 = \hat{\mathbf{s}}\cos\gamma + \mathbf{n}\sin\gamma \quad (\mathbf{n}\perp\hat{\mathbf{s}} \text{ 为 0 相位参考方向}) \tag{3.7}
$$

$$
\psi(t) = \varphi_0 + \omega\,(t - t_0) \quad (\varphi_0 \text{ 锚定分析起点 } t_0) \tag{3.8}
$$

$$
\mathbf{b}(t) = R(\hat{\mathbf{s}}, \psi(t))\, \mathbf{b}_0 \tag{3.9}
$$

其中 $R(\hat{\mathbf{s}}, \psi)$ 为绕 $\hat{\mathbf{s}}$ 转 $\psi$ 的旋转（四元数 $(\cos\psi/2,\ \hat{\mathbf{s}}\sin\psi/2)$）。**单/双向扫描**：$\psi(t)$ 取三角波（单向为 $\psi$ 从 Start 单调到 Stop 后停住；双向为在 $[\text{Start}, \text{Stop}]$ 间往返）：

$$
p = (\varphi_0 + \omega\,(t - t_0)) \bmod 2L, \qquad L = \text{Stop} - \text{Start}
$$

$$
\psi(t) = \text{Start} + \begin{cases} p, & p \le L \\ 2L - p, & \text{otherwise} \end{cases} \tag{3.10}
$$

**自检**：任意时刻 $\lvert \mathbf{b}(t)\cdot\hat{\mathbf{s}} \rvert = \cos\gamma$ 恒成立（附录 A 逐点验证）；同参数两次运行逐点一致（确定性）。这是相对 ATK 的实质性改进：ATK Spinning 初始相位未初始化（ASLR 绑定），而自研引擎 $\varphi_0$ 显式锚定 $t_0$，结果完全可复现。

## 3.7 External 外部指向文件

ATK 语法：`Point <Sensor> External "<FilePath.sp>"`。格式为 ATK/STK 外部指向文件（时间 + 四元数或欧拉角序列）。自研引擎 P3 实现：解析 .sp → 时间插值（线性/四元数 slerp）→ 逐时刻视轴。**GUI 文档标注 ".pattern 文件等"，格式需在实施时用样例文件确认**。

# 第 4 章　传感器视场模型（Pattern）

> **本章导读（白话）**：镜头"能照到多大、什么形状"叫视场。本章把 5 种视场（圆/方/环/聚光/条带）都写成一组"夹角不等式"，这是覆盖判定的核心。
>
> **背后的理论**：视场本质是一个**角域**（目标方向相对镜头轴的夹角范围），形状由传感器工作原理决定。普通相机 = 圆锥（离轴角 ≤ 半角）；相机阵列/画幅 = 矩形锥（横竖两个半角）；环形扫描 = 内外圆锥 + 钟角（一个"甜甜圈/披萨角"）；雷达/通信 = 半功率波束宽度（由频率与天线直径算出）；SAR = 入射角带 + 前后排除角（一个斜扫的条带）。这些在航天/天线/雷达教科书里都有标准定义。

## 4.1 通用覆盖判定框架

对时刻 $t$、目标点 $P$：计算目标方向 $\hat{\mathbf{u}} = (P - \mathbf{r}_{\mathrm{sat}})/\lVert \cdot \rVert$，变换到传感器系得 $\hat{\mathbf{u}}_s$（3.1），再做视场不等式。**输出仍是覆盖窗口**：粗筛 10 s + 边界 1 s 精化（现有 P1 机制不变），仅判定函数替换。圆目标（默认 5 km）保留现有"足印∩目标圆"语义：对复杂视场，用圆心 + 圆周 8 个采样点做模式判定（任一命中即覆盖），多边形目标沿用网格点。

## 4.2 SimpleCone 简单圆锥

$$
\text{covered} \Leftrightarrow \hat{\mathbf{u}}_s \cdot \hat{\mathbf{z}}_s \ge \cos\eta \ (\text{即离轴角 } \theta \le \eta) \ \text{且} \ \varepsilon \ge \varepsilon_{\min} \tag{4.1}
$$

对天底指向时 (4.1) 与现有 $\lambda \le \lambda_{\max}(\eta, h)$ 完全等价（附录 A 自检：$\theta \le \eta \Leftrightarrow \lambda \le \lambda_{\max}$）。

## 4.3 Rectangular 矩形（视锥模型，**注意与直觉差异**）

ATK 参数：垂直半角 V、水平半角 H。**正确模型是相机视锥**，不是"方位角/高度角各自限幅"：

$$
\text{covered} \Leftrightarrow \lvert \operatorname{atan2}(\hat{\mathbf{u}}_s\cdot\hat{\mathbf{x}}_s,\ \hat{\mathbf{u}}_s\cdot\hat{\mathbf{z}}_s) \rvert \le H \ \text{且} \ \lvert \operatorname{atan2}(\hat{\mathbf{u}}_s\cdot\hat{\mathbf{y}}_s,\ \hat{\mathbf{u}}_s\cdot\hat{\mathbf{z}}_s) \rvert \le V \tag{4.2}
$$

等价形式（z_s > 0 且在视轴前方）：

$$
\lvert x_s / z_s \rvert \le \tan H \ \text{且} \ \lvert y_s / z_s \rvert \le \tan V \tag{4.3}
$$

**自检发现**：最初按球坐标 $\lvert az \rvert \le H$ 且 $\lvert el \rvert \le V$ 建模是错误的——视轴上 $el = 90^\circ$，任何有限 $V$ 都会把视轴本身排除在外；(4.2) 的视锥形式对视轴、斜对角方向都正确，且保持 $\text{SimpleCone}(\theta) \subseteq \text{Rect}(\theta, \theta)$ 的内接关系（附录 A 已验证）。ATK 实测 Rect(45,45) 比 SimpleCone45 覆盖更长（74 vs 69 窗口），与矩形面积更大一致。

## 4.4 Conical 复杂圆锥

ATK 参数：内锥半角 $\theta_{\min}$、外锥半角 $\theta_{\max}$、最小/最大钟角 $\varphi_{\min}/\varphi_{\max}$：

$$
\text{covered} \Leftrightarrow \theta_{\min} \le \theta \le \theta_{\max} \ \text{且} \ \varphi_{\min} \le \varphi \le \varphi_{\max} \tag{4.4}
$$

其中 $\theta = \arccos(\hat{\mathbf{u}}_s\cdot\hat{\mathbf{z}}_s)$ 为离轴角，$\varphi = \operatorname{atan2}(\hat{\mathbf{u}}_s\cdot\hat{\mathbf{x}}_s, \hat{\mathbf{u}}_s\cdot\hat{\mathbf{y}}_s)$ 为绕视轴的钟角（从 $y_s$ 参考起算，顺时针；0° 参考待校准）。**退化一致性**：$\text{Conical}(0, 45, 0, 360) \equiv \text{SimpleCone}45$（附录 A 2 万方向采样逐点一致；ATK 实测 69/69 窗口一致）。

**钟角怎么理解**：圆锥本身是"离轴角在一定范围"，但很多扫描/成像传感器只"扫某一圈"，所以要再加一个"绕镜头轴转了多少"（钟角）的限制——这样就能表示"半个甜甜圈""一瓣披萨"这种部分环。钟角 0° 朝哪个参考方向因软件而异（3.8 节注明待校准）。

## 4.5 HalfPower 半功率

ATK 参数：频率 f（GHz）、天线直径 D（m）。抛物面天线半功率波束宽度（HPBW）经验公式（Balanis；Wikipedia Parabolic antenna 亦载 k≈70）：

$$
\mathrm{HPBW} \approx 70\,\lambda / D \ (\text{度}), \qquad \lambda = c / f \tag{4.5}
$$

$$
\eta = \mathrm{HPBW} / 2 = 35\,\lambda / D \ (\text{度}) \tag{4.6}
$$

然后用 $\text{SimpleCone}(\eta)$ 判定（(4.1)）。**自检**：14.5 GHz/1 m → $\eta = 0.72^\circ$（ATK 官方默认）；0.5 GHz/0.35 m → $\eta \approx 60^\circ$（实验标称 60° 波束），均吻合。

## 4.6 SAR（合成孔径雷达条带）

ATK 参数（GUI"地面仰角、排除角、是否跟踪父对象高度、高度"；XML `<SAR><MinElevAngle><MaxElevAngle><FwdExclAngle><AftExclAngle><Altitude><TrackParentAlt>`）：

**模型（与 STK `IAgSnSARPattern` 官方定义一致）**：

$$
\text{covered} \Leftrightarrow \varepsilon_{\min}^{\mathrm{SAR}} \le \varepsilon_{\mathrm{ground}}(P) \le \varepsilon_{\max}^{\mathrm{SAR}} \ \text{且} \ \angle(\hat{\mathbf{u}}, \hat{\mathbf{v}}_{\mathrm{fwd}}) \ge \psi_f \ \text{且} \ \angle(\hat{\mathbf{u}}, -\hat{\mathbf{v}}_{\mathrm{fwd}}) \ge \psi_a \tag{4.7}
$$

其中：

- $\varepsilon_{\mathrm{ground}}(P)$ = 目标点 $P$ 处观测卫星的仰角（沿用现有几何公式）：

$$
\tan\varepsilon = \frac{\cos\lambda - R/r}{\sin\lambda} \tag{4.8}
$$

其中 $\lambda$ 为目标点与卫星地心投影的地心角、$r$ 为卫星地心距（推导见 `docs/理论报告.md` 公式 (6)，本报告附录 A 已用 ENU 直接矢量法复核一致）；
- $\hat{\mathbf{u}}$ = 卫星→目标单位方向；$\hat{\mathbf{v}}_{\mathrm{fwd}}$ = 沿迹向单位向量（ECI 或 ECF 速度投影到本地水平面）；
- $\psi_f / \psi_a$ = 前/后排除角：目标方向与速度正向/反向的夹角下限（STK 原文："the minimum angle between the forward/aft projection of the velocity vector and the vector to the target"）。

物理含义：**地面仰角带** $[\varepsilon_{\min}^{\mathrm{SAR}}, \varepsilon_{\max}^{\mathrm{SAR}}]$ 决定跨迹向条带（近天底 $\varepsilon$ 大被 $\varepsilon_{\max}^{\mathrm{SAR}}$ 排除 → 条带中间有孔洞；远缘 $\varepsilon$ 小被 $\varepsilon_{\min}^{\mathrm{SAR}}$ 排除）；**前后排除角**决定沿迹向长度（排除正前方/正后方，束宽 $= 180^\circ - \psi_f - \psi_a$，中心在侧视方向）。

**父高度（Altitude/TrackParentAlt）**：STK 语义 = "sensor's parent object altitude（assumed constant）"。ATK rc.5 的跟踪开关不生效（§10.28），项目已用各星 TLE 平均高度近似；自研引擎天然按实际轨道高度逐时刻计算（更正确）。**待校准**：ATK 在"不跟踪父高度"时用固定 Altitude 参与换算的方式（8.3 节 P3 用已记录窗口反推）。

**自检**（附录 A）：550 km 高度、$\varepsilon \in [12^\circ, 70^\circ]$、$\psi_f = \psi_a = 30^\circ$ 时，近天底点（$\varepsilon \approx 78^\circ$）被排除、条带中部（$\varepsilon \approx 31^\circ$）覆盖、远缘（$\varepsilon \approx 6^\circ$）被排除、前向点（前向角 $29^\circ < 30^\circ$）被排除——四条物理判据全部符合。

## 4.7 幅宽换算（保留现有口径）

幅宽 W（km）仍按 `docs/理论报告.md` 公式 (7)(8) 换算为等效视场半角（逐时刻高度），仅低轨生效，GEO/高轨自动回退视场半角（现有规则不动）。

## 4.8 从判定到覆盖窗口

复用现有两段式：10 s 粗筛检测 → 1 s 边界精化（横跨全程窗口跳过、按连续覆盖段切分内部空隙）；输出/选星 1 分钟片解耦。判定函数替换为 (4.1)-(4.7) 的任意组合（传感器类型 + 指向 + 姿态），窗口合并/裁剪/过滤逻辑不变。

# 第 5 章　约束建模

> **本章导读（白话）**：除了"照得到"，还有一堆"什么时候才算数"的附加条件——距离太远不行、仰角太低不行、太阳不能直射镜头、白天黑夜等等。这就是约束。
>
> **背后的理论**：约束全是"**几何量 + 不等式筛选**"。几何量（距离、方位角、仰角、各项变化率、太阳/月球方向）都能由位置速度逐时刻解析算出；满足区间才把该时刻算作有效覆盖。约束不改变输出格式（仍是覆盖窗口），只是让窗口变少、变短——这与 ATK 软件的行为一致（加约束后报告形态不变，只是覆盖更少）。

## 5.1 通用框架

约束是**逐时刻附加判定**：`covered(t) = pattern_ok(t) 且 constraint_ok(t)`（Include 语义）；`ExcludeIntervals` 取反（约束满足的区间被排除）。约束不改变输出形态——ATK 验证报告已确认加约束后仍是同一份覆盖窗口报告。

作用对象分三级（与 ATK GUI/worker 一致）：**目标点（facility）**、**每颗星传感器（sensor）**、**每颗星（satellite）**。同一物理量在不同对象上定义不同（如目标点的仰角 vs 传感器的俯仰角，见 5.2）。

## 5.2 基本约束（12 种）与公式

| 约束 | 对象 | 计算公式 |
| --- | --- | --- |
| AzimuthAngle 方位角 | 目标点/平台 | 目标点：大圆方位角 $az = \operatorname{atan2}(\sin\Delta\lambda\cos\varphi_s,\ \cos\varphi_t\sin\varphi_s - \sin\varphi_t\cos\varphi_s\cos\Delta\lambda)$，$\Delta\lambda = \lambda_s - \lambda_t$（卫星减目标经度）；平台：目标在本地系水平面投影方向角 |
| ElevationAngle 仰角 | 目标点/平台 | 目标点：(4.8) 的 $\varepsilon$；平台：目标在本地系的俯仰角（向下为负） |
| Range 距离 | 任意 | $\lVert \mathbf{r}_{\mathrm{sat}} - \mathbf{r}_{\mathrm{tgt}} \rVert$ |
| AzimuthRate | 任意 | $d\,az/dt$（时间栅格中心差分） |
| ElevationRate | 任意 | $d\varepsilon/dt$ |
| RangeRate | 任意 | $d\,\mathrm{Range}/dt$（径向相对速度，与多普勒相关） |
| AngularRate 角变化率 | 任意 | $\lVert d\hat{\mathbf{u}}/dt \rVert$（视线单位向量的变化率） |
| Altitude 高度 | 目标点 | 目标点相对参考球/椭球的高度（地面网格为 0；用户可设） |
| PropagationDelay 传播延时 | 任意 | $\mathrm{Range} / c$ |
| LineOfSight 视线 | 任意 | 线段是否被地球遮挡：对地目标等价于 $\varepsilon \ge 0$；星间用"线段到地心最小距离 $\ge R$" |
| fieldofview 视场 | 传感器 | 目标在视场不等式内（与 pattern 判定同源，作为显式开关） |
| TerrainMask 地形 | 目标点 | 需 DEM（后期实现；本期声明为"考虑中"，不生效时按无遮挡） |

变化率类约束统一用中心差分（10 s 粗筛栅格；精化边界附近重新计算），避免解析求导的符号错误，精度对约束判定足够。

**这些约束为什么设计成这样**：它们来源于三类现实要求——①**质量**（仰角太低大气路径长、画质差，用最小仰角卡）；②**链路**（距离、相对速率、角速率决定能否稳定建立联系/测量）；③**光学安全**（太阳/月球不能直射镜头或视线方向，否则传感器受损或图像过曝）。逐条都是"一个几何量的区间要求"，所以统一用"开关 + Min/Max"来配置。

## 5.3 光照约束（7 种）

| 约束 | 计算公式 |
| --- | --- |
| SunElevationAngle 太阳仰角 | 太阳方向在对象本地 ENU 系的仰角 |
| SunGroundElevAngle 太阳地平仰角 | 太阳方向在目标点 ENU 的仰角（昼夜判断） |
| LunarElevationAngle 月球仰角 | 月球方向在对象本地 ENU 的仰角 |
| LOSSunExclusion 视线太阳规避角 | $\angle(\text{视线方向}, \hat{\mathbf{s}}) \ge$ 阈值 |
| LOSLunarExclusion 视线月球规避角 | $\angle(\text{视线方向}, \hat{\mathbf{m}}) \ge$ 阈值 |
| BSSunExclusion 视轴太阳规避角 | $\angle(\text{视轴 } \mathbf{b}, \hat{\mathbf{s}}) \ge$ 阈值（光学传感器避光） |
| BSLunarExclusion 视轴月球规避角 | $\angle(\text{视轴 } \mathbf{b}, \hat{\mathbf{m}}) \ge$ 阈值 |

太阳/月球方向由 skyfield（生产）或 Meeus 解析（降级）给出（1.3 节）。

## 5.4 实现注意

- 约束区间语义：Min/Max 同时填 = 闭区间；只填一边 = 单侧；AzimuthAngle 必须成对（ATK 要求）；
- ExcludeIntervals/IncludeIntervals 附加选项在窗口后处理实现；
- 约束全部向量化（T 维数组），不引入逐时刻 Python 循环。

# 第 6 章　区域覆盖率

> **本章导读（白话）**：单个点好判断，"一整片区域被覆盖了多少"怎么量化？本章把区域撒成网格点，逐时刻统计被覆盖的点占比，得到区域覆盖率。
>
> **背后的理论**：这是"区域覆盖率"的经典做法——**网格离散化**。逐时刻覆盖率 = 被覆盖网格点数 / 总网格点数，1 分钟序列给出覆盖率的时序变化。它与 ATK 的"区域覆盖定义（区域网格）"口径一致，已对拍 480/480 分钟一致。优点是能直接回答"这片区域覆盖得怎么样"，缺点是精度受网格间距限制（0.2° 约 22 km）。

多边形/圆区域维持现有网格模型（`make_grid_points` 0.2° 或用户粒度）。扩展一个输出项：**逐时刻覆盖率 = 被覆盖网格点数 / 总网格点数**，分钟序列可与选星/报表联动。该口径与 ATK 覆盖定义（CD 区域网格）的 `Percent Coverage` 等价——**已对拍 480/480 分钟覆盖与否 100% 一致、覆盖率最大差 0.00039**（ATK 实验记录 §10.13/§7.8）。复杂传感器/姿态下该输出项自动沿用（网格点逐一过 4.1 判定）。

# 第 7 章　数值实现要点与性能

> **本章导读（白话）**：公式再漂亮，程序要跑得快、不出错。本章讲实现层面的"向量化、数值稳定、性能预算"。
>
> **背后的理论**：三维几何全用 numpy 数组**整段算**（不逐点 Python 循环），所以几千颗星 × 上万个时刻仍能秒级完成；归一化、clip、角度 wrap 用来防止浮点病态和边界翻车；复杂度是"卫星数 × 时刻数"量级，是问题本身的规模，没有额外放大。这些是数值计算的通用工程原则，不是某个领域专有技巧。

## 7.1 数据流

```
每颗星每时刻：
  r_TEME, v_TEME ──(1.1)(1.2)──▶ r_ECEF, v_ECEF
      └──▶ 姿态族 DCM (2.2)-(2.5) ──(+偏移四元数 (2.6))──▶ C_body←ECI
      └──▶ 指向 (第3章) ──▶ 视轴 b(t) ──▶ C_s←ECI
  目标点 P ──▶ û ──(3.1)──▶ û_s ──(4.1)-(4.7)──▶ covered(t)
  约束 (第5章) ──▶ covered_final(t)
  ──▶ 窗口合并（现有两段式）
```

实现上：新模块 `attitude_geometry.py`（姿态族 + 四元数）、`sensor_geometry.py`（指向 + 视场 + 约束）；`coverage_analysis.py` 的 `analyze_one_satellite` 增加配置参数 `attitude_cfg / pointing_cfg / sensor_cfg / constraints`，覆盖判定函数替换，其余不动。

## 7.2 数值稳定性

- 叉积后归一化；投影公式对退化方向防护（分母 < 1e-12 时给出明确异常）；
- arccos 参数 clip 到 [−1, 1]；角度统一用 atan2/度-弧度明确转换；
- 四元数复合后归一化；
- 钟角/方位角 wrap 到 [0°, 360°)；转速连续累计（不重置）保证长时段扫描正确。

**为什么归一化这么重要**：姿态/视场全是**单位方向**的运算——差一点归一化，后续夹角/投影就会累积误差，长时段、大卫星数下会放大成明显的错误窗口。同理，`arccos` 的输入必须 clip 到 $[-1,1]$，否则浮点噪声会让它报 `nan`。这些是数值计算的"卫生习惯"，保证了结果的稳定和可复现。

## 7.3 性能预算

单星单时刻新增成本：2 次坐标系变换（$3\times3$ 矩阵乘）+ 视场不等式（$\le 10$ 次三角函数）。相对现有"星下点 + haversine + 足印"增加的浮点量很小；且复杂引擎统一用底层 `sgp4_array` 矢量传播 + 手写 GMST 旋转，绕开了 skyfield 高层封装，**整体反而更快**（见下方实测）。量级估计仍是"卫星数 × 时刻数"（$N\times T$），约束与姿态不改变复杂度量级。

**4000 颗星实测（2026-08-23，星链 4000 × 8 h × 杭州 5 km 圆，10 s 粗筛 + 1 s 精化，单机）**：

| 引擎/配置 | 耗时 | 窗口数 |
| --- | --- | --- |
| 旧版 skyfield 简单圆锥 45° | 309 s | 1677 |
| 复杂·SimpleCone45 + P0 姿态 | 32.6 s | 1650 |
| 复杂·Rectangular 45,45 | 33.3 s | 1792 |
| 复杂·SAR 12/70/30/30 | 41.6 s | 5615 |

**结论**：①4000 颗星级别，复杂引擎全部在 ~40 s 内，完全可跑；②各复杂类型（P0/矩形/SAR）之间耗时接近（32~42 s），说明几何增量远小于传播开销——大头是"传播 + 逐星循环"，视场/姿态类型几乎没有额外负担；③复杂引擎比旧版 skyfield 路径快约 10 倍，因为使用了底层 `sgp4_array`，这是本实现带来的附带性能收益。**报告 7.3 原预测"复杂版慢 1.5～2 倍"不成立，以本条实测为准。**

## 7.4 接口与回归

- CLI/GUI 入口复用现有 `run_atk_windows` 的参数结构（`sensor_type / sensor_params / pointing / constraints / attitude` 已定义在 `atk_ui.py` 的 TOML 持久化），自研引擎读同一配置 → **双引擎同一套配置语义**；
- 回归：`validate_china_remote`、`validate_n2yo_crosscheck`、`validate_sensor_params`、AppTest 全页签。

# 第 8 章　理论自检与验证方案

> **本章导读（白话）**：怎么证明"算对了"？本章就是整套验证体系——不靠"我觉得对"，而是用"退化一致 + 与 ATK 对照 + 零回归 + 数值自检 + 物理量级检查"多管齐下。详见 8.6 专门讲"公式正确性如何保证"。

## 8.6 公式正确性如何保证（核心问题）

"这些公式是怎么保证对的？"——答案分七层，由弱到强、由"定义"到"证明"：

**① 公式来自业界标准定义，不是自造。**
每个模型都能在权威来源找到出处，本文公式不是拍脑袋写的：

| 模型 | 出处（参考文献） | 性质 |
| --- | --- | --- |
| 姿态族 0-4 | ATK `ICEnum.h` 枚举 `EVeProfile` + ATK 离线帮助 | 软件既定语义 |
| SAR 入射角带/排除角 | STK DevKit `IAgSnSARPattern` 官方定义 | 行业标准定义 |
| 半功率波束 | Balanis《Antenna Theory》（HPBW ≈ 70λ/D） | 天线学公认公式 |
| 太阳/月球位置 | Meeus《Astronomical Algorithms》 | 天文历表标准 |
| 四元数/旋转矩阵 | Markley & Crassidis《Spacecraft Attitude》 | 姿态数学标准 |

**② 退化一致性：把复杂参数退回简单情形，必须回到已知对的答案。**
这是最"硬"的一类检验——如果新公式在特殊参数下不能还原成旧版已验证的结果，那一定错了：

| 退化 | 应得到 |
| --- | --- |
| 复杂圆锥(0, 45, 0, 360) | ≡ 简单圆锥 45°（已数值验证 + ATK 68/68） |
| 半功率用半角后 | ≡ 简单圆锥(η) |
| 姿态族 P0 无偏移 | ≡ 旧版"正下方"（逐窗口一致） |
| SAR 全程仰角、无排除 | ≡ 整半球 |

**③ 与 ATK 专业软件对拍（同一输入，输出必须接近）。**
最有力的外部对照：同一个卫星、目标、时段，ATK 与自研各算一次，比覆盖窗口。实测四种复杂传感器总时长偏差都在 3% 以内（SAR 待最后一项校准，约 29%）。

**④ 零回归：默认路径与旧版逐窗口一致。**
简单圆锥 + 正下方（用户最常用）走的是"委托旧引擎"的路径，结果一个窗口都不变——证明新代码没有破坏已验证的旧功能。

**⑤ 数值自检（135 项，全过）。**
写过一套自动校验脚本，逐条检查公式的"数学性质"：旋转矩阵是否正交（$C C^{\mathsf{T}} = I$）、偏移四元数是否保长度、GrazingAlt 视线是否真正与球面相切、旋转扫描离轴角是否恒为锥角、退化一致采样是否逐点相等、Meeus 太阳方向是否与 skyfield 一致（0.21°）……这都是公式"自身的一致性"检查。

**⑥ 物理合理性与量级检查。**
用常识看结果对不对：GrazingAlt 的下俯角应与"同高度地平线"同量级；SAR 近天底应出现"条带孔洞"；矩形应与"面积更大的视野"对应更长覆盖。反直觉的结果往往藏 bug。

**⑦ 确定性与诚实边界。**
同参数两次运行逐窗口一致（可复现）；同时如实声明还剩哪些**待校准**项（SAR 父高度语义、Fixed matrix 六元素、欧拉/YPR 符号、钟角 0° 参考、Spinning 相位参考方向），这些不藏着，列入 3.8 清单，等 ATK 实测反推。

**一句话总结**：公式"对"靠的是——① 用标准定义（有出处）；② 退化一致（能回到已证对的答案）；③ 外部对拍（跟成熟软件一致）；④ 数值自检（自身数学性质成立）；⑤ 物理量级合理（直觉相符）。五层都过，才有底气说"够工程用"。最后一项"待校准"是诚实标注的已知边界，不是隐瞒的问题。

# 第 10 章　结论与已知边界

> **本章导读（白话）**：任何模型都有边界。本章如实交代"哪些可靠、哪些还没做或有简化"，避免让人误以为万无一失。
>
> **背后的理论**：科学建模必须"贴地说明适用条件"——边界来自几个不变的事实：传感器口径（视场半角=视线张角、幅宽逐星生效）、地球是椭球（这里用球近似）、姿态动力学（这里只回答"给定指向，覆盖几何是什么"，不回答"卫星转得够不够快"，那属于调度约束）。这些边界不是 bug，是明确的约定，讲清楚才能让人放心用。

## 结论

1. **数学封闭**：姿态族（第 2 章）、指向（第 3 章）、视场（第 4 章）、约束（第 5 章）全部有显式解析公式，可逐时刻计算；
2. **理论已自检**：135 项数值检查全过（8.1），并修正了矩形视锥这一关键口径；
3. **可对拍**：ATK 已有基准数据覆盖全部传感器类型与姿态族（8.3），逐项可验证；
4. **确定性优于 ATK**：Spinning 相位显式锚定分析起点，同参数完全可复现；
5. **不重复造轮子**：轨道外推（SGP4/skyfield）、太阳/月球（skyfield/Meeus）、时间栅格与窗口合并全部复用现有已验证代码。

## 已知边界（如实声明）

- 地形遮挡（TerrainMask）需 DEM，本期不做，默认无遮挡；
- External 指向文件格式（.sp/.pattern）需样例确认后实现；
- SAR 父高度的 ATK 精确换算语义、Fixed matrix 六元素重建、欧拉/YPR 符号、钟角 0° 参考、Spinning 相位参考方向，均列入 3.8 待校准清单，用 ATK 实测反推；
- 姿态动力学（真实卫星的控制律/机动能力约束）不建模——本报告只回答"给定姿态指向，覆盖几何是什么"，不问"卫星能不能转那么快"（后者属调度约束，后续可加角速度/角加速度限制）；
- 目标圆语义：复杂视场用圆心+圆周 8 点采样近似，与现有"足印∩目标圆"的精确重叠比例（circle_overlap_ratio）口径略有差异（5 km 圆边缘效应，ATK 本身也是点判定）。
